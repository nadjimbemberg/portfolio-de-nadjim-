Le projet se compose de deux briques séparées mais complémentaires : un frontend qui gère l'expérience utilisateur, et une API REST qui expose et sécurise les données. Cette séparation reproduit une architecture professionnelle client/serveur découplée.

Conception et développement de la solution applicative

Frontend — mds-avis (Next.js 14, App Router, TypeScript, Tailwind CSS) :

  • Parcours d'authentification complet : connexion, inscription, mot de passe oublié / réinitialisation.
  • Consultation des avis publics, création et modification des avis personnels.
  • Espace profil utilisateur et panneau d'administration réservé au rôle admin, pour valider les avis en attente.
  • Composants réutilisables (Navbar, StarRating) et utilitaires centralisés dans lib/ (appels API, authentification, types TypeScript partagés).

Backend — API-avis (Express 5, TypeScript) :

  • 14 endpoints organisés par domaine : authentification (/register, /login, /forgot-password, /reset-password, /logout), gestion des avis (CRUD sur /avis), profil (/me, /change-password), modération (/authorize/avis/:id).
  • Architecture en couches : routes/ → controllers/ → middleware/ (validation, authentification), avec Prisma comme ORM.
  • Authentification par JWT + hachage des mots de passe en Argon2 ; session invalidée via un système de version de token (tokenVersion) lors d'une déconnexion ou d'un changement de mot de passe.
  • Envoi d'e-mails (réinitialisation de mot de passe) via Nodemailer.
Gérer les données

Base de données PostgreSQL hébergée sur Neon, modélisée avec Prisma (prisma/schema.prisma + migrations versionnées). Le modèle gère des avis pouvant être créés de façon anonyme ou authentifiée, des comptes utilisateurs avec rôle (utilisateur / admin), et un mécanisme de révocation de session par versionnage de token. Un seed initial permet d'amorcer un compte administrateur pour la modération.
